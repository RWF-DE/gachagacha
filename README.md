# よーそろがちゃ（電波祭2026）

「よーそろがちゃ」（YOSORO GACHA）は、電波祭の本部テントに置いた iPad 1台で、来場者が無料の景品抽選をするためのアプリです。
**インターネットがなくても iPad の中だけで動きます**（静的 HTML/CSS/JS + Service Worker + IndexedDB の PWA）。
ビルド作業・外部サービス・外部CDNは不要です。仕様の詳細は [docs/DESIGN.md](docs/DESIGN.md) を参照してください。
名前・配色・景品などを変えれば、**ほかのイベントでも**使えます（下の「ほかのイベントで使う」。設計は [docs/CUSTOMIZE.md](docs/CUSTOMIZE.md)）。

- 参加者（電波祭2026の設定）：「本校の学生」は学籍番号（既定は数字7桁ちょうど。スタッフ画面で変更可）を入力（電波祭の両日で1回）、「本校学生以外」は学籍番号の入力なしで1回（抽選の前に2問の**アンケート**に答えます。下の「来場者アンケート」参照）。個人情報は集めません。
- 抽選：日ごとに独立した「引いたら戻さないくじ箱」。乱数は `crypto.getRandomValues`。結果は **IndexedDB に保存が完了してから** 演出が始まります。
- スタッフ：結果画面の「お渡し済み・OK」を **1秒長押し** で確定し、次の人へ進みます。

## ほかのイベントで使う

名前・配色・回すもの・参加の方法・アンケート・景品と日程は、**コードを書き換えなくても**、初回セットアップとスタッフ画面で変えられます（電波祭2026の設定は「テンプレート」として入っています）。

### 変えられるもの

- **名前と文字**：ガチャ名・欧文名・イベント名・ロゴの文字（和／欧文）・待機画面の帯の文字・景品の呼び方（「お宝」など）。文字数の上限は入力欄の右上に出ます。長い名前は、画面に収まるよう自動で小さくなります。
- **配色**：プリセット7つ（よーそろ・若葉・桜・海・夜祭・墨・鉄紺）、または4色（地・主色・文字・差し色）を自分で選ぶカスタム。読みにくい組み合わせには「注意」が出ます（保存はできます）。
- **回すもの**：舵輪・ガチャ玉・ガラポン・歯車・ルーレット・風車・さくらの7種。抽選画面で回す図形で、待機画面・結果画面の飾りも同じ図形になります。「舵輪を回して、お宝を引こう！」などの文言も、これに合わせて変わります。
- **参加の方法**：学生（学籍番号で参加済みを確認）／一般の方／両方。一般の方に、抽選の前のアンケートを**出す・出さない**。入口の見出しと補足の文字。1つだけにしても待機画面は出ます（入口の行が1つになります）。
- **アンケートの質問と選択肢**：2つの質問の見出し・選択肢・注意書き（下の「来場者アンケート」）。
- **景品・賞・開催日**：追加と削除、名前、賞の演出の系統（特別・レア・通常。順位ではなく演出の派手さです）、結果画面の欧文の飾り、「本数未定」の印、日ごとの初期本数。上限は、賞12・景品40・開催日7（1〜7日）です。

### どこで変えるか

- **初回セットアップ**（新しい iPad、または「全初期化」のあと）：
  - 手順1「はじめかた」で、**電波祭2026**（前回と同じ設定）・**新しいイベント（汎用）**（ガチャ玉・若葉の配色・1日・特賞／レア賞／参加賞の仮の設定）・**設定ファイル**のどれかから始めます。データが消えたときは、左下の「バックアップから復元する」。
  - 手順3「イベントの基本」で名前・ロゴの文字・配色・回すもの・参加の方法・開催日数、手順4「景品と本数」で開催日・賞・景品・日ごとの本数を決めます。
- **スタッフ画面**（ロゴを3秒長押し → PIN）：
  - 「**景品・日程**」：開催日・賞・景品・日ごとの初期本数。
  - 「**イベント**」：名前と表示（帯の文字・景品の呼び方もここ）・配色・回すもの・参加の方法。
  - 「**アンケート**」：集計と、「質問と選択肢」の編集。
  - 「**バックアップ・リセット**」：バックアップ、設定ファイルの書き出し・読み込み、本番リセット。
  - 変えた内容は、スタッフ画面を閉じるとプレイヤー画面に反映されます（配色だけは、「イベント」の中ですぐ変わります）。

### 景品・賞・開催日の追加と削除のきまり

記録を壊さないために、次のきまりがあります。できない操作のボタンは押せない状態になり、理由が出ます。

- **景品を足す**：いつでもできます。すでに抽選が始まった日は、その景品の本数が0本から始まります（「在庫」の「± 調整」で入れます。理由がログに残ります）。
- **景品を消す**：まだ一度も当たっていない景品だけ消せます。当たったことのある景品は消せないので、代わりに残数を0にします（「在庫」の「± 調整」）。景品は最低1つ必要です。
- **日ごとの初期本数**：その日にまだ抽選がないときだけ変えられます。抽選が始まった日は「変更不可」の表示になり、増やす・減らすは「在庫」の「± 調整」で行います。
- **名前の変更**（景品・賞・開催日）：いつでもできます。過去の抽選記録には、抽選した時点の名前が残ります。
- **賞を足す・消す**：足すのはいつでも。消せるのは、景品が1つもなくなった賞だけです（賞は最低1つ必要）。
- **開催日を足す・消す**：日は末尾に足されます（初期本数は1日目と同じ値から）。消せるのは**最後の日だけ**で、その日にまだ抽選がなく、「開催中」の日でもないときです（開催中なら、「状態」で別の日に切り替えてから）。
- 「景品・日程」は、画面の下の **「保存する」** を押すまで何も変わりません（変更があると「未保存の変更があります」が出ます）。保存せずに別のタブへ移ったり閉じたりすると、変更は捨てられます。削除の確認は出ないので、消しすぎたら、保存せずにタブを開き直してください。

### 設定ファイルで、ほかの iPad や次のイベントを準備する

**設定ファイル**は、イベントの設定だけを入れた JSON ファイルです（名前・配色・回すもの・参加の方法・アンケートの質問・景品と賞・開催日・日ごとの**初期本数**）。**抽選履歴・学籍番号・アンケートの回答・PIN・効果音の設定は入りません**（残数ではなく初期本数が入ります）。

1. 設定を済ませた iPad で、スタッフ画面 → 「バックアップ・リセット」→ **「設定ファイルを書き出す」** → 「保存・共有する」（AirDrop / ファイル / メール等で、もう1台へ送る）。
2. 読み込む iPad で：
   - **まだセットアップしていない iPad**：初回セットアップの手順1「はじめかた」→ **「設定ファイルを読み込む」**。内容が入るので、PIN を決めて最後まで進みます（途中で名前や本数を直せます）。
   - **すでにセットアップした iPad**：スタッフ画面 → 「バックアップ・リセット」→ **「設定ファイルを読み込む」** → 内容を確認して「読み込む」。読み込めるのは **抽選履歴が1件もないときだけ** です（リハーサルをしたあとは、先に「本番リセット」。必要ならその前にバックアップ）。PIN と効果音の設定は今のまま、在庫はファイルの初期本数で作り直され、開催日は最初の日に戻ります。
3. 同じ iPad で次のイベントを始めるときも同じです（本番リセットで履歴を消してから、設定ファイルを読み込む。最初からやり直すなら「全初期化」→ 初回セットアップ）。

**バックアップ**（「バックアップを書き出す」）との違い：バックアップは抽選履歴・学籍番号・アンケートの回答・PIN まで**すべて**を書き出し、復元すると今のデータをすべて置き換えます（データが消えたときや iPad の交換のため）。設定ファイルは、イベントの設定だけです。

### 使える文字（フォント）

同梱のフォントには、JIS 第1水準漢字・かな・英数字と、アプリの画面に書かれている文字が入っています。名前や景品名などに **それ以外の文字**（橙・菫などの第2水準以降の漢字、旧字体・異体字、絵文字）を使うと、その文字だけ iPad の標準の書体で表示されます（読めますが、書体が少し変わります）。欧文の欄（欧文名・ロゴの文字（欧文）・賞の欧文）は半角の英数字と記号だけです。

ほかのイベント専用に公開する場合は、「公開（デプロイ）の方法」の「ほかのイベント専用に配置するとき」も見てください。

## ファイル構成

```
index.html / manifest.webmanifest / sw.js   アプリ本体・PWA
css/   tokens.css（色の役割・書体）・app.css（共通部品・スタッフ画面）・poster.css（プレイヤー画面・演出）
js/    app.js（画面の流れ・見た目の反映）・admin.js（スタッフ画面・初回セットアップ）・db.js（IndexedDB）・lottery.js（抽選）
       config.js（定数・既定の設定）・templates.js（テンプレート：電波祭2026 / 新しいイベント）・profile.js（設定の正規化・設定ファイル・景品と日程の規則）
       theme.js（配色）・motifs.js（回すもの）・survey.js（アンケートの検証・集計）
       stage.js / screens.js / poster.js（ポスター画面・演出）・perf.js（?perf=1 の計測表示）・sound.js（効果音）
fonts/ 自前ホストのフォント（woff2・OFL。dev/build-fonts.py で作り直せる）
icons/ ホーム画面アイコン（dev/render-icons.mjs で icon.svg から書き出し。--motif / --theme で別のイベント用の絵も作れる）
tests/ *.test.mjs（単体）・db.browser.mjs（実際の IndexedDB）・e2e.mjs / e2e-custom.mjs（Playwright）
docs/  DESIGN.md（仕様）・CUSTOMIZE.md（ほかのイベントで使うための設計）
```

すべて相対パスなので、どのフォルダに置いても動きます。

内部の識別子（IndexedDB 名・キャッシュ名・バックアップと設定ファイルの `app` フィールド・PIN の塩・CSV のファイル名の `yosoro-gacha`）は、アプリの名前やイベントを変えても**そのままです**（変えると、すでに iPad にあるデータやバックアップが読めなくなるため）。

景品の `id` も端末内の在庫と抽選記録の参照に使います。ブルダック炒め麺からカムジャ麺への変更では `bulldak` を維持し、既設端末に残る旧名称は起動時に表示名だけ更新します。

## 公開（デプロイ）の方法

どちらも「フォルダの中身をそのまま置くだけ」です。**HTTPS で配信されることが必須**です（Service Worker の条件）。

### A. denpasai.jp に置く
このフォルダの中身を、サーバーの `public/gacha/` にコピーします。
→ `https://denpasai.jp/gacha/` で開けます。

### B. GitHub Pages
`main` への push で GitHub Actions が自動デプロイします（下の「iPadで動作確認（GitHub Pages）」を参照）。

### 更新して再公開するとき
ファイルを変更したら **`sw.js` の先頭の `VERSION` を 1 つ上げて** から公開してください（上げないと iPad は古いキャッシュを使い続けます）。
iPad 側では、スタッフ画面の「状態」→「更新を適用」で切り替えます（未確認の抽選が無いときだけ押せます。本番中に自動で再読み込みはしません）。
`js/`・`css/`・`fonts/` にファイルを追加したときは `sw.js` の `PRECACHE` にも追加してください（同じ項目を2回書くと、Service Worker のインストールが失敗して、オフラインで動かなくなります）。GitHub Actions が、公開の前に「`PRECACHE` の項目が実在する・重複がない・`js/` `css/` `fonts/` のファイルが全部載っている」ことを確かめ、だめなら公開しません。
フォント（`fonts/*.woff2`）は、JIS 第1水準漢字＋かな＋英数字に、画面の文言（`js/`・`css/`・`index.html` に書かれた文字）を加えたサブセットです。画面の文言を増やしたら `python3 dev/build-fonts.py`（要 fonttools・brotli・npm）で作り直してください。スタッフ画面で入力した名前などの文字は対象外で、フォントに無い字は iPad の標準の書体で表示されます（上の「使える文字（フォント）」）。

### ほかのイベント専用に配置するとき（任意）

名前・配色などは、アプリの中（スタッフ画面）で変えれば足ります。次のものだけは **ファイルに書かれた固定の値** なので、そのイベント専用の配置を作るときに、配置ごとに書き換えます。

- `manifest.webmanifest`：`name`・`short_name`・`description`・`background_color`・`theme_color`（ホーム画面や起動画面に使われます）。
- `index.html`：`<title>`・`description`・`theme-color`・`apple-mobile-web-app-title`（最初に描かれるときの値。起動したあとは、アプリが設定の名前と配色で `<title>`・`theme-color`・`apple-mobile-web-app-title` を書き換えます）。
- アイコン：`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers node dev/render-icons.mjs --motif capsule --theme wakaba` のように、回すもの（`--motif`）と配色（`--theme`）を選ぶと、`icons/icon.svg` を作り直して PNG も書き出します（選べる id は `--help`。引数なしなら、今の `icon.svg` から PNG だけを書き出します）。
- 書き換えたら `sw.js` の `VERSION` を上げます（アイコンも `PRECACHE` の対象です）。

ホーム画面に追加するときの名前の欄は、その場で書き換えられます。

## iPad への入れ方（本番の前日までに）

1. iPad を Wi-Fi につなぎ、Safari で公開URLを開く。
2. 初めて開くと、自動で **「初回セットアップ」** が出ます。次の6つの手順を進めて「はじめる」を押します（電波祭2026の設定のままなら、内容を確認して進むだけです。手順2以降は、左下の「戻る」で前の手順に戻れて、入力は残ります）。
   1. **はじめかた**：「電波祭2026（よーそろがちゃ）」（前回と同じ設定。最初から選ばれています）／「新しいイベント（汎用）」／設定ファイルを読み込む、のどれか。データが消えたときは、左下の「バックアップから復元する」。
   2. **PIN**：スタッフ画面に入るための4〜8桁の数字（2回入力。忘れないよう控えておく）。
   3. **イベントの基本**：ガチャ名・欧文名・イベント名・ロゴの文字（和／欧文）・配色・回すもの・参加の方法（学生／一般の方／アンケートを出すか）・開催日数。帯の文字と景品の呼び方は、あとから「イベント」タブで変えます。
   4. **景品と本数**：開催日の名前、賞・景品、日ごとの初期本数。「本数未定」の景品には警告が出ます（0本のままだと当たりません）。
   5. **学籍番号のルール**：文字（数字のみ／英数字）と桁数（既定は数字7桁ちょうど）。学生が参加しない設定のときは、この手順は飛ばされて5つの手順になります。
   6. **最後の準備**：保存領域の保護の許可・今日の開催日・設定内容の確認。
3. 画面左上の **ロゴ（電波祭2026では、小さな舵輪マークと「電波祭 2026 / DENPASAI 2026」の文字）を3秒長押し** → PIN → **「状態」で「オフライン準備完了」と表示されるまで待つ**（数十秒）。「保存領域の保護」も「保護されています」になるのが望ましい（許可を求めるボタンあり）。
4. Safari の共有ボタン → **「ホーム画面に追加」**（ホーム画面に出る名前の欄は、ここで書き換えられます）。
5. **ホーム画面のアイコンから起動**する（以後はこちらを使う。Safari で開いたデータとは別の保存領域になることがあるため、セットアップはアイコンから起動した状態でやり直すのが確実。Safari で設定を済ませていたなら、先に「設定ファイルを書き出す」をしておくと、アイコンからの初回セットアップの手順1で読み込めます）。
6. **機内モードにして**、アイコンから起動して抽選が最後までできることを確認する（リハーサル）。
7. リハーサルのデータは、スタッフ画面「バックアップ・リセット」→ **本番リセット**（「リセット」と入力＋PIN）で消す。

## iPadで動作確認（GitHub Pages）

- `main` へ push すると、GitHub Actions（`.github/workflows/pages.yml`）が単体テストを実行し、通れば実行に必要なファイルだけを組み立て、`sw.js` の `PRECACHE`（項目が実在する・重複がない・`js/` `css/` `fonts/` のファイルが全部載っている）を確かめたうえで GitHub Pages にデプロイします（Actions タブから手動実行も可）。
- **初回のみ**：リポジトリの Settings → Pages → Source を **「GitHub Actions」** にしてください。
- URL：https://rwf-de.github.io/gachagacha/ （組織名は小文字）
- iPad の Safari でこの URL を開き、上の「iPad への入れ方」の手順で確認します。
- 注意：**非公開リポジトリの Pages は GitHub Team 以上のプランが必要**です。使えない場合は、上の「A. denpasai.jp」の `public/gacha/` に置くか、リポジトリを公開にしてください。
- 更新して再デプロイするときは、これまで通り `sw.js` の `VERSION` を上げてください。

## 来場者アンケート（一般の方だけ。既定は「本校学生以外の方」）

**目的**：使い回し・連続参加の歯止めと、協賛企業（学習塾など）へ「どんな人が来ているか」を説明するためのデータです。学生には出ません。

**来場者に見える流れ**（電波祭2026の設定）：「本校学生以外の方」→ **Q1 年齢**（1つ選ぶ。選ぶと自動で次へ）→ **Q2 来場のきっかけ**（複数選択可・1つ以上選ぶと「次へ（舵輪へ）」が押せる）→ 舵輪で抽選。
どちらの画面にも「回答は個人が分からない形で集計し、電波祭の運営と協賛企業への来場者層の説明に使います。」と「アンケート 1/2」が出ます。「戻る」で前の質問に戻れ（答えは残る）、最初の画面まで戻ると答えは消えます。入力途中で放置すると90秒で最初の画面に戻ります（答えも消えます）。氏名・連絡先・自由記述の欄はありません。

**アンケートを出さないとき**：スタッフ画面 → 「イベント」→「参加の方法」の「一般の方に、抽選の前のアンケートを出す」を外して「保存」すると、一般の方は入口を選ぶとそのまま抽選に進みます（回答は保存されません。出さない間の抽選は、集計で「未回答」になります）。この設定でも、これまでの記録の集計は見られます。

**保存**：答えは抽選が保存されるときに、その抽選の記録に一緒に保存されます（途中でやめたら何も残りません）。このiPadの中とバックアップ（JSON）にだけあり、サーバーには送りません。設定ファイルには入りません。個人は特定できません。

**スタッフの見方・書き出し**（スタッフ画面 → 「アンケート」タブ）：
- 「全日程」と開催日ごとのボタンを切り替えて、一般の抽選数・回答あり・未回答、Q1（既定は年齢）の分布、Q2（既定はきっかけ）の人数と割合（複数選択なので合計は100%を超えます）、Q1×Q2のクロス表を見られます。
- **「集計をCSVで書き出す」**：表示している範囲の集計表を CSV にします（協賛企業への説明資料用。Excel で文字化けしないよう BOM つき）。全日程分が欲しいときは「全日程」にしてから書き出してください。
- 「バックアップ・リセット」→「CSV」（確認用の抽選一覧）にも、一般の方の行に Q1・Q2 の列（列の名前は質問の「短い名前」。既定は「年齢」「きっかけ（／区切り）」）が入ります。アンケートを出していなかった間の記録・導入前の記録・旧バックアップの分は「未回答」と表示されます。

**質問と選択肢の変更**（スタッフ画面 → 「アンケート」タブの下の「質問と選択肢」。上の「質問と選択肢を編集」ボタンで移動できます）：
- Q1（1つ選ぶ）・Q2（複数選べる）それぞれの **見出し**（40字まで。「/」は「ここで改行してよい」の印で、画面には出ません）・**短い名前**（10字まで。集計・CSVの見出しに使います）・**選択肢**（追加・名前の変更・削除。Q1は2〜12個、Q2は2〜10個。1つ24字まで。同じ名前は使えません）と、**注意書き**（80字まで。2つの質問の画面に出ます。空なら出しません）を直して「保存」します。質問は2つのままで、数や形式（1つ選ぶ／複数選べる）は変えられません。
- 選択肢の名前を直しても、内部の **id は変わりません**。これまでの回答は同じ選択肢として集計されます（表示は新しい名前）。足した選択肢には新しい id が付きます。
- **削除した選択肢**にも、これまでの回答は残り、集計に「**旧選択肢**」として出ます（回答には、答えたときの名前が保存されています。確認用のCSVにもその名前が出ます）。
- 直した内容は、保存してスタッフ画面を閉じたあとに来る人から使われます。コードの書き換えや `sw.js` の `VERSION` の更新は要りません。使った文字がフォントに無いと、その字だけ iPad の標準の書体になります（上の「使える文字（フォント）」）。
- テンプレートの初期値（電波祭2026・新しいイベント）を変えたいときだけ、`js/templates.js` の `SURVEY_AGES` / `SURVEY_TRIGGERS` などを直します（`id` は変えず `label` だけ。直したあとは `sw.js` の `VERSION` を上げます）。

IndexedDB のバージョン・ストアは変えていないので、すでに本番データがあるiPadにもそのまま更新できます。

- データが消えてしまった：初回セットアップ画面の「バックアップから復元する」、またはスタッフ画面「バックアップから復元」で最新のバックアップを読み込みます。
- 「保存領域の保護」が未許可のままの場合：Safari の履歴/サイトデータ消去でデータが消えることがあります。こまめにバックアップしてください。
- PINを忘れた：スタッフ画面に入れません。バックアップがあれば、Safari の「サイトデータを削除」後に復元する方法があります（運営責任者へ）。

## 音が鳴らないとき

効果音はアプリの中で作っています（音声ファイルなし）。iPad で音が出ないときは、上から順に確認してください。

1. **iPad 本体**：音量ボタンで上げる／コントロールセンターの**消音（ベルのマーク）**を解除する（古い機種はサイドスイッチ）／**Bluetooth スピーカー・イヤホン**につながっていないか確認（つながっていると音はそちらへ出ます）。
2. **画面を一度タップ**：アプリを開いた直後、画面ロックや別アプリから戻った直後は、iPad の仕様で**最初のタップのあと**に音が有効になります。故障ではありません。
3. **スタッフ画面で確認**：ロゴ3秒長押し → PIN → 「設定」タブの「効果音」。
   - 状態の表示：**「再生できます」**なら準備OK。「画面をタップすると有効になります」「中断中（タップで再開）」は画面をもう一度タップ。「オフ（設定）」は「効果音を鳴らす」をオンにして音量を上げる。「この端末では使えません」は Safari を最新にするか、別の iPad で確認。
   - **「テスト音を鳴らす」**を押して鳴るか確認（このボタンを押すこと自体が、音を有効にするタップになります）。
4. それでも鳴らないとき：ホーム画面のアプリを一度完全に終了して開き直し、最初に1回タップ。

仕組みのメモ：
- iPad の Safari は、指が**触れた瞬間**（touchstart / pointerdown）では音を有効にできず、**離したとき**（touchend / pointerup / click）から有効になります。`js/sound.js` はこの離したときに AudioContext を作って再開し、止まる（中断・ロック復帰）たびに次のタップでやり直します。
- 本体の消音スイッチ中でも鳴らすため、`navigator.audioSession.type = 'playback'` を設定します（この機能がある iPad）。それに加えて、**iPad では常に**、無音の音声（全サンプル 0 の WAV）をループ再生して再生用の状態に保ちます（実機で未確認の部分への二重の備え。アプリが見えなくなったら止め、次のタップで再開。iPad 以外では何もしません）。ループが再生中でないあいだ、スタッフ画面の状態は「画面をタップすると有効になります」になります。
- 音量は効果音ごとに最大の大きさ（ピーク）を揃えて最後に簡易リミッターを通しています（`volume=1.0` のとき 大きな場面は約 −2 dBFS、タップ音は約 −9 dBFS）。スタッフ画面の音量スライダー（初期 0.7）はその後ろにかかります。

```sh
# 単体テスト（抽選・学籍番号の正規化/検証・設定の正規化と設定ファイル・景品と日程の規則・バックアップ検証・アンケートの検証/集計・配色・回すもの・文字の割り付け）
npm test                    # = node --test tests/*.test.mjs   （Node 20 以上）

# 実際の IndexedDB での db.js の確認（Playwright + Chromium。画面は使わず、js/db.js を直接呼ぶ）
npm run test:db             # = node tests/db.browser.mjs

# E2E（Playwright + Chromium。サーバーは自動で起動）
npm run e2e                 # 基本の流れ（tests/e2e.mjs）
npm run e2e:custom          # カスタマイズの流れ（tests/e2e-custom.mjs）
```

- `test:db` と `e2e` は、ブラウザの場所を `PLAYWRIGHT_BROWSERS_PATH`（既定 `/opt/pw-browsers`）で指定します。
- E2E と DB の確認は `playwright` を `/opt/node22/lib/node_modules/playwright` から読み込みます。別の場所なら `PLAYWRIGHT_MODULE=/path/to/playwright` を指定。
- 配信するフォルダは `E2E_ROOT=/path` で変更できます（既定はこのリポジトリ）。
- 演出は `?fast=1` で1秒未満に短縮されます（E2Eで使用）。
- E2E が操作する要素：`data-testid="spin-button"`（タップでまわす）、`wheel`（舵輪）、`result-card`（結果カード）。

### 演出のなめらかさを実機で確認する（`?perf=1`）

URL の末尾に `?perf=1` を付けて開くと（例：`https://…/gacha/?perf=1`）、画面の右上に小さな表示が出ます（付けなければ何も出ません）。
抽選の入力直後から結果カードが出るまでの描画間隔を記録し、演出ごとに1行で表示します：

```
sponsor  frames: 330, >33ms: 1, max: 41 ms (@0.2s)
```

`frames` = 描画した回数、`>33ms` = 2フレーム以上止まった回数、`max` = いちばん長く止まった時間（`@` は入力からの経過秒）。目安は `>33ms` が 0〜2 回・`max` が 50 ms 未満です。
この数字はメインスレッド（JavaScript 側）の描画間隔だけです。舵輪の空転や CSS の演出は iPad のコンポジタ（GPU 側）で動くので、この数字が悪くても画面はなめらかなことがあります。見た目のカクつきは画面収録で確認してください。
カクつきの調査用で、本番では付けません。動かし方のルール（transform / opacity だけ・clip-path を動かさない・先に描いておく）は docs/DESIGN.md「10. デザイン方針」の「性能」を参照してください。

## プライバシー

- 学籍番号は「参加済みの確認」だけに使い、端末（IndexedDB）内にのみ保存します。サーバーには送信しません。URL・ログ・エラーメッセージにも出しません。

- バックアップ（JSON）とCSVには学籍番号とアンケートの回答が含まれます。**イベント終了後、iPad のデータ（スタッフ画面「全初期化」）と、書き出したバックアップ/CSV のファイルを削除してください。** 設定ファイル（イベントの設定だけ）には、学籍番号・アンケートの回答・PIN は入りません。
